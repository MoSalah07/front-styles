# Conventions for design-eg

Read this before writing any component. It is the contract that keeps work from
several people in parallel looking like one library.

## Where files go

| What | Path | Registry type |
| --- | --- | --- |
| Primitive (Button, Dialog) | `packages/ui/src/components/<name>.tsx` | `registry:ui` |
| Composite block (PricingTable, DataTable) | `packages/ui/src/blocks/<name>.tsx` | `registry:block` |
| Whole page (LoginSplit, DashboardShell) | `packages/ui/src/templates/<name>.tsx` | `registry:block` |
| Hook | `packages/ui/src/hooks/<name>.ts` | `registry:hook` |
| Test | `<same folder>/<name>.test.tsx` | not published |

File names are kebab-case. Exported components are PascalCase.

**Never edit `src/index.ts`.** It is generated by `scripts/gen-barrel.mjs`, which
the build runs. Editing it by hand causes conflicts and gets overwritten.

## File template

```tsx
"use client"; // only if the component uses hooks, state, or event handlers

/** One sentence describing the component. This becomes its registry description. */
import * as React from "react";
import { Dialog as DialogPrimitive } from "radix-ui";
import { cn } from "../lib/cn";

export type FooProps = React.ComponentProps<typeof DialogPrimitive.Root>;

function Foo({ className, ...props }: FooProps) {
  return <DialogPrimitive.Root data-slot="foo" className={cn("...", className)} {...props} />;
}

export { Foo };
```

Rules embedded in that template:

- The **file-level doc comment** must be the first thing after any `"use client"`.
  It is published as the component's description, so write a real sentence.
- Every component accepts `className` and merges it through `cn()` last, so
  consumers can always override.
- Every element carries `data-slot="<name>"` for styling and testing hooks.
- Props extend the underlying element or Radix primitive rather than being
  re-declared by hand.
- Import Radix from the unified package: `import { Dialog as DialogPrimitive } from "radix-ui"`.
  Namespaces available: AccessibleIcon, Accordion, AlertDialog, AspectRatio,
  Avatar, Checkbox, Collapsible, ContextMenu, Dialog, Direction, DropdownMenu,
  Form, HoverCard, Label, Menubar, NavigationMenu, Popover, Portal, Progress,
  RadioGroup, ScrollArea, Select, Separator, Slider, Slot, Switch, Tabs, Toast,
  Toggle, ToggleGroup, Toolbar, Tooltip, VisuallyHidden.
- Import the class helper as `import { cn } from "../lib/cn"` from `components/`,
  or `"../lib/cn"` from `blocks/` and `templates/` too (same depth).

## Styling rules

**Use tokens, never raw values.**

| Never | Always |
| --- | --- |
| `bg-[#e50914]`, `bg-red-600` | `bg-primary`, `bg-destructive`, `bg-brand-600` |
| `z-50` | `z-(--z-modal)`, `z-(--z-popover)` |
| `h-10` on a control | `h-(--control-h-md)` |
| `rounded-lg` on a card | `rounded-card` |
| `ml-2`, `pr-4`, `left-0`, `text-left` | `ms-2`, `pe-4`, `start-0`, `text-start` |
| `duration-150` | `duration-(--duration-fast)` |
| `shadow-md` | `shadow-1`, `shadow-2`, `shadow-3` |

Logical properties are not optional. The library is RTL-first, and a single
`ml-2` breaks Arabic layouts. Use `ms/me`, `ps/pe`, `start/end`, `text-start`,
and `rtl:` only when a transform needs mirroring.

Available semantic colours: `background`, `foreground`, `card`, `popover`,
`surface-1/2/3`, `primary`, `primary-hover`, `primary-active`, `secondary`,
`muted`, `accent`, `destructive`, `success`, `warning`, `info`, `border`,
`input`, `ring`, `overlay`, `brand`, `chart-1..5`, `sidebar*`, each with a
matching `-foreground` where text sits on it.

Z-scale: `--z-base`, `--z-raised`, `--z-sticky`, `--z-dropdown`, `--z-overlay`,
`--z-modal`, `--z-popover`, `--z-toast`, `--z-tooltip`.

## Accessibility

- Every interactive element has an accessible name. Icon-only buttons need
  `aria-label`.
- Focus is always visible: `focus-visible:ring-2 focus-visible:ring-ring`.
- Disabled uses `disabled:opacity-50 disabled:pointer-events-none`; invalid uses
  `aria-invalid:` variants.
- Animate with `motion-safe:` so reduced-motion users are respected.
- Prefer a Radix primitive over hand-rolling keyboard behaviour.

## Radix gotchas that have already bitten us

- **`Slot` takes exactly one child.** With `asChild`, do not render a sibling or
  a conditional `null` next to `children`; branch and return a separate element.
  See `components/button.tsx`.
- **Do not put `disabled` on a Slot** that may wrap an `<a>`. Use `aria-disabled`.
- A server component cannot take an event handler prop. Anything with `onClick`,
  `onSubmit` or `useState` needs `"use client"`.

## Dependencies

Core deps (already installed): `radix-ui`, `class-variance-authority`, `clsx`,
`tailwind-merge`.

Optional peers, already installed and declared, use freely where they fit:
`cmdk` (command palette), `sonner` (toasts), `input-otp` (OTP field),
`react-hook-form` + `@hookform/resolvers` + `zod` (forms), `recharts` (charts).

**Do not add any other npm dependency.** If something seems to need one, write it
by hand or leave a TODO and report it.

## Tests

Each component gets `<name>.test.tsx` covering, at minimum: it renders, its
accessible name is correct, and its main interaction works.

```tsx
import { render, screen } from "@testing-library/react";
import userEvent from "@testing-library/user-event";
import { describe, expect, it } from "vitest";
import { Foo } from "./foo";
```

Radix components that portal need `document.body` queries; prefer
`screen.getByRole` over container queries.

## Before you finish

Run these from the repo root and make sure they pass:

```bash
pnpm --filter @design-eg/ui build
pnpm --filter @design-eg/ui test
pnpm --filter @design-eg/ui typecheck
pnpm format
```

Do not commit. Do not touch `src/index.ts`, `package.json` dependency lists, or
any file outside the folders your task assigned you.
